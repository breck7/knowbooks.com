The document supplies the words.

Hash the Scroll. Use its own vocabulary to spell the result in camelCase. Same document, same phrase. Change the text, and its checko usually changes dramatically.

We encode 72 hash bits. More distinct words mean a shorter checko: 64 words need 12; 16 need 18; two need 72. Repeats are allowed. Fewer than two distinct words cannot produce a useful word-only checko.

Useful for comparing copies, not proving authorship. For a fixed vocabulary, an accidental pair match is about 1 in 4.7 sextillion; deliberate collision search takes roughly 2³⁶ work. This is a new encoding, not a new cryptographic hash.

Exact v1 rules
  1. Normalize CRLF and CR to LF. Remove top-level checko lines. Collapse trailing newlines to one LF. All other text, indentation, punctuation and Unicode remain significant.
  2. Extract letter/combining-mark tokens. Lowercase, keep only A–Z words, deduplicate and sort alphabetically. V1 does not use numbers or non-A–Z words as vocabulary; they still affect the hash.
  3. Hash UTF-8 bytes of checko:v1\n followed by the normalized text. The prefix ends in an actual LF.
  4. Interpret SHA-256’s first 72 bits as an unsigned big-endian integer. For N distinct words, use the smallest L with Nᴸ ≥ 2⁷². Write that integer as L base-N digits, padding on the left with zeros; each digit indexes the sorted vocabulary.
  5. Join the words in camelCase. Store checko v1 yourCamelCasePhrase; this reserved metadata line is excluded. Compare phrases exactly. Freeze these rules for v1.

This fingerprints text, not a parsed tree. A tiny edit is not guaranteed to change every word, and collisions remain possible. The vocabulary is local to each document; no outside words are introduced.
